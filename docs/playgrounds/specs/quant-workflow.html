Quant Workflow

Turn the AI-quant video's research pipeline into one tool-true command: mt5 quant run drives the native MT5 tester across a symbol × timeframe matrix — genetic optimization, in-sample/out-of-sample forward validation, configurable selection gates — and emits a ranked quant.v1 envelope plus a dependency-free report. The user's EA stays the only source of alpha; the harness never writes a strategy.

Intent

Decision this informs: the public contract for a campaign command — matrix expansion, the per-cell hybrid (optimize → pick winner → re-run FULL), selection gates and ranking, envelope shape, artifacts, and error codes — before any implementation lands.

Anti-pattern this prevents: dragging the video's Python research engine and vectorized backtester into a CLI whose charter is “no strategy logic, no indicator math, no pandas … not a separate Python backtester.” The campaign orchestrates native tester runs only. Second anti-pattern: ranking on out-of-sample numbers alone, which flatters a trending long-only asset whose OOS curve is the market, not the edge.

Current vs target

Current — one cell at a time, by hand

  • tester ea optimize runs one (symbol, timeframe) at a time; the trader re-launches per asset and per timeframe.
  • scanner() exists but only runs raw single-mode tests across symbols — no optimization, no IS/OOS, no ranking.
  • Picking the winner, splitting in/out-of-sample, gating on trades/PF, and ranking are all manual — the video's “500 clicks, 5 hours” problem.

Target — one campaign, ranked output

  • quant run expands a symbol×timeframe matrix and drives each cell through the hybrid validation below.
  • Configurable gates (min trades, min PF) + a ranking metric pick survivors; rejects are recorded with reasons.
  • One quant.v1 envelope + a dependency-free HTML report (ranked table, per-strategy IS/OOS/FULL card, inline-SVG equity curve, caveats).
  • Child runs still register under results/, so tester list/show keep working.

Per-cell flow — the hybrid (forward optimize + FULL re-run)

Each cell is one (symbol, timeframe). Steps run serially — the launcher contract forbids parallel terminals (TERMINAL_ALREADY_RUNNING). native MT5 steps launch terminal64.exe; pure steps are stdlib-only, no terminal, unit-tested with fixtures.

Optimize on the matrix cell native MT5
ea.optimize(mode="genetic", forward=split, params=…, from=FULL, to=FULL) → optimization.xml with a back (in-sample) and forward (out-of-sample) result per pass. MT5 owns the split. mt5_cli/tester/ea.py:152 · genetic = _OPT_MODES["genetic"] (ea.py:18) · forward param already threaded (ea.py:160)
Pick the winner from the passes pure
selection.pick_winner(passes, rank_by) — choose the pass whose in-sample clears the gates, best by the ranking metric; extract its parameter set → write a .set. Reads: mt5_cli/tester/results.py:285 (parse_optimization_xml) — extend to expose back-vs-forward columns per pass
Re-run the winner over the FULL range native MT5
ea.single(set_file=winner.set, from=FULL, to=FULL) → one continuous report.html: the merged equity curve crossing the split marker + FULL stats. mt5_cli/tester/ea.py:45 (single, set_file path) · stats from results.py:184-256
Assemble the cell pure
IS & OOS metrics from the winner's XML row, FULL metrics from the re-run, equity curve split at the forward date. One cell record.

Cost: ~2 native launches per cell. Edge direction is proven by the stress precedent — ea.stress() already calls single() in a serial loop and grades the result (mt5_cli/tester/ea.py:335-360); the campaign reuses that shape one altitude up, swapping “delay rung” for “matrix cell” and “robustness score” for “ranked survivors.”

Campaign matrix — explore the cost

The matrix is symbols × timeframes, each cell ~2 native launches, run serially. This is the video's “30 minutes for 10 asset classes” budget made explicit — and the reason --dry-run prints the plan before committing a terminal for an hour.

8 cells × ~2 launches = 16 native runs

Serial by contract: the launcher refuses a second terminal64.exe while one is running, so wall-clock is the sum, not the max. A --dry-run returns this plan (cells, launch count, the expanded matrix) and launches nothing.

Selection & ranking — explore the contract

Hard gates decide who survives; the ranking metric decides the order; the rest are rejected with a reason. The GOLD trap (why OOS alone never ranks). Rank by oos_sharpe or full_net and GOLD tops the table — but the video is explicit that gold ran up ~150–200% over the window, so a long-only strategy posts a beautiful out-of-sample curve that is the asset, not the edge. That is why the contract gates min-PF on the in-sample segment (where selection happens) and treats OOS as a validated flag, not the sole ranking key. Honest reporting over a flattering number.

Failure semantics follow the repo's frozen shape (mt5_cli/reports/envelope.py, locked by the envelope-contract test): a cell whose optimize or re-run fails ships its fail envelope in rejected with reason: "CELL_FAILED" and the campaign continues; the command only fails outright when no cell produces a ranked or rejected record (e.g. an empty matrix). Schema-version style mirrors stress.v1 and wake.v1.

Command contract

mt5 --json quant run \
  --expert my_strategy \
  --symbols EURUSD,XAUUSD,UKOIL,USDJPY \
  --tf H1,H2 \
  --from 2022-01-01 --to 2024-12-31 \
  --split 0.70 \                 # IS/OOS boundary: fraction or YYYY-MM-DD (maps to MT5 forward)
  --param Risk=0.5,0.5,3.0 \     # MT5 optimization range: start,step,stop  (repeatable)
  --param ATRWindow=10,5,30 \
  --mode genetic \
  --min-trades 300 --min-pf 1.0 --oos-min-pf 1.0 \
  --rank-by oos_sharpe --per-asset 2 \
  [--modelling ohlc-1m] [--no-html] [--dry-run] [--timeout 1800]

mt5 --json quant list            # campaigns, newest first
mt5 --json quant show <campaign-id>
  • Exit code stays 0; callers parse the envelope's ok boolean (repo-wide rule).
  • run is CLI-only (launches a terminal, long-running). list/show are read-only and MCP-safe — matching how tester runs are not exposed over MCP.
  • --per-asset 2 keeps the top two per asset, exactly the rank-1/rank-2 layout of the video's summary table.

Operating as a quant — the agent loop

The commands are hands; this loop is the role. It ships as a static agent playbook (mt5_cli/skills/QUANT_WORKFLOW.md, the USER_WORKSPACE.md precedent) so any agent can introspect it. The agent brings the hypotheses and authors the EA — its own capabilities; the tool never holds the alpha.

Frame the hypothesis — one or two sentences: what edge, which assets/timeframes, why it persists. Keep rules simple; complex rules curve-fit.
Author & compile the EA — write the rule in ./ea/, expose search params as inputs, mt5 ea compile.
Plan, then run the campaign — quant run … --dry-run to see the cost, then run with gates --min-trades 300 --min-pf 1.0 --rank-by oos_sharpe.
Read quant.v1 and judge — start at the top rank, then apply the discipline below; do not stop at the headline number.
Stress the winner — tester ea stress on the winning set; require robustness.verdict robust/degraded before trusting it.
Iterate — refine hypothesis/params, re-run, log what lived or died and why.
The judgment that makes it quant, not curve-fitting.
  • Asset-drift trap: a long-only winner on a trending asset (gold +150–200%) shows a gorgeous OOS curve that is the asset, not the edge. Subtract the drift — if the edge vanishes, it was never there.
  • Statistical weight: trust nothing under ~300 trades.
  • IS↔OOS consistency: a validated entry whose OOS tracks its in-sample beats a higher-ranked one that only shines out-of-sample.
  • Overfitting: wide grids + genetic search find lucky corners; fewer, meaningful params win.

Spec seed

Ownership boundaries

  • New package mt5_cli/quant/ owns the campaign; it imports mt5_cli.tester.ea and writes zero strategy logic.
  • matrix.py — pure: expand/validate symbols×timeframes, parse --split (fraction or date), parse --param ranges.
  • selection.py — pure: pick winner from passes, apply gates, rank, record rejects (the tester/stress.py analog).
  • report.py — pure: dependency-free HTML + inline-SVG equity curve. No matplotlib, no pandas.
  • campaign.py — orchestration: per-cell hybrid, serial launches, artifacts, quant.v1 assembly.
  • store.py — campaign-id + manifest.json read/write (reuses tester/cache.py conventions).
  • mt5/cli.py stays a thin flag-parsing wrapper (CONTRIBUTING architecture rule).
  • mt5_cli/skills/QUANT_WORKFLOW.md — static agent playbook (the loop + judgment), shipped like USER_WORKSPACE.md.

Public interfaces

  • quant.campaign.run(*, expert, symbols, timeframes, from_date, to_date, split, params, mode, selection, …) → quant.v1
  • quant.list_campaigns() / quant.get_campaign(id)
  • mt5 quant run | list | show
  • One parsing extension: results.parse_optimization_xml gains back-vs-forward awareness.
  • Errors: EMPTY_MATRIX, INVALID_SPLIT, NO_WINNER (registered in mt5_cli/errors.py, test-enforced).

Build sequence

  • 1 — matrix.py (expansion, split, param ranges) + tests
  • 2 — forward-aware parse_optimization_xml + fixtures
  • 3 — selection.py (winner pick, gates, ranking) + tests
  • 4 — campaign.py orchestration against a fake launcher
  • 5 — report.py (HTML/SVG) + store.py + tests
  • 6 — CLI group + error registry + quant agent playbook (ships with the CLI)
  • 7 — README / AGENTS / describe catalog / CHANGELOG; flip spec & plan status

Non-goals (YAGNI)

  • No Python EDA engine (return distribution, weekday×hour heatmap, autocorrelation) — that needs numpy/pandas the charter excludes.
  • No Python vectorized backtester and no Python→MQL5 translation — MT5 stays the only engine; the EA stays the only alpha.
  • No walk-forward beyond the single forward split; no multi-data-feed / news (CPI/FOMC/NFP) testing.
  • No campaign resume in v1 (each child run is cached, so resume can come later).
  • No trading strategy, signal generation, indicator math, or market opinion.
