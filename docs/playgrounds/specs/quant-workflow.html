Quant Workflow

Turn the AI-quant video's research pipeline into one tool-true command: mt5 quant run drives the native MT5 tester across a symbol × timeframe matrix — genetic optimization, in-sample/out-of-sample forward validation, configurable selection gates — and emits a ranked quant.v1 envelope plus a dependency-free report. The user's EA stays the only source of alpha; the harness never writes a strategy.

Intent

Decision this informs: the public contract for a campaign command — matrix expansion, the per-cell hybrid (optimize → pick winner → re-run FULL), selection gates and ranking, envelope shape, artifacts, and error codes — before any implementation lands.

Anti-pattern this prevents: dragging the video's Python research engine and vectorized backtester into a CLI whose charter is “no strategy logic, no indicator math, no pandas … not a separate Python backtester.” The campaign orchestrates native tester runs only. Second anti-pattern: ranking on out-of-sample numbers alone, which flatters a trending long-only asset whose OOS curve is the market, not the edge.

Current vs target

Current — one cell at a time, by hand

  • tester ea optimize runs one (symbol, timeframe) at a time; the trader re-launches per asset and per timeframe.
  • scanner() exists but only runs raw single-mode tests across symbols — no optimization, no IS/OOS, no ranking.
  • Picking the winner, splitting in/out-of-sample, gating on trades/PF, and ranking are all manual — the video's “500 clicks, 5 hours” problem.

Target — one campaign, ranked output

  • quant run expands a symbol×timeframe matrix and drives each cell through the hybrid validation below.
  • Configurable gates (min trades, min PF) + a ranking metric pick survivors; rejects are recorded with reasons.
  • One quant.v1 envelope + a dependency-free HTML report (ranked table, per-strategy IS/OOS/FULL card, inline-SVG equity curve, caveats).
  • Child runs still register under results/, so tester list/show keep working.

Per-cell flow — the hybrid (forward optimize + FULL re-run)

Each cell is one (symbol, timeframe). Steps run serially — the launcher contract forbids parallel terminals (TERMINAL_ALREADY_RUNNING). native MT5 steps launch terminal64.exe; pure steps are stdlib-only, no terminal, unit-tested with fixtures.

Optimize on the matrix cell native MT5
ea.optimize(mode="genetic", forward=split, params=…, from=FULL, to=FULL) → the back-result optimization.xml (all passes, in-sample) plus MT5's separate .forward report (only the selected best passes, out-of-sample). One pass row does not hold both. ForwardMode=1/ForwardDate: ini_builder.py:107-109 · ea.py:152 · genetic=_OPT_MODES (ea.py:18) · forward threaded ea.py:221
Join back↔forward, pick the winner pure
passes.join() pairs back↔forward rows by pass id; selection.pick_winner() takes the best forward-covered pass clearing the in-sample PF gate, by rank_by, and reads its parameter columns → a .set. New mt5_cli/quant/passes.py wraps results.parse_optimization_xml (results.py:285, back/forward-blind today) · .set via ini_builder.render_set (ini_builder.py:181-212)
Re-run the winner over the FULL range native MT5
ea.single(set_file=winner.set, from=FULL, to=FULL) → one continuous report.html: the merged equity curve crossing the split marker + FULL stats. mt5_cli/tester/ea.py:45 (single, set_file path) · stats from results.py:184-256
Assemble the cell pure
IS from the back row, OOS from the forward row, FULL from the re-run; equity curve split at ForwardDate. One cell record.

Cost: 2 native launches per cell in the common path (1 optimize writes both reports, 1 FULL re-run). Fallback +1: if the winner was not forward-tested (no .forward row) or the report lacks the needed metric columns, an explicit single(from=split, to=FULL) produces OOS directly. Edge direction is proven by the stress precedent — ea.stress() already calls single() in a serial loop (mt5_cli/tester/ea.py:335-360); the campaign reuses that shape one altitude up.

Open mechanism choice. The forward path is fiddlier than it looks (separate .forward file, only top passes forward-tested, join by pass id), so the simpler explicit two-pass mechanism — optimize IS-window → pick → single OOS-window → single FULL, a flat 3 launches/cell, no .forward parsing — may be the better default. The spec keeps the hybrid (the brainstorm choice) with this explicit rerun already specced as the fallback, so flipping the default is a one-line contract change.

Campaign matrix — explore the cost

The matrix is symbols × timeframes, each cell ~2 native launches, run serially. This is the video's “30 minutes for 10 asset classes” budget made explicit — and the reason --dry-run prints the plan before committing a terminal for an hour.

8 cells × 2 launches = 16 native runs (+1 on cells needing the OOS-rerun fallback)

Serial by contract: the launcher refuses a second terminal64.exe while one is running, so wall-clock is the sum, not the max. A --dry-run returns this plan (cells, launch count, the expanded matrix) and launches nothing.

Selection & ranking — explore the contract

Hard gates decide who survives; the ranking metric decides the order; the rest are rejected with a reason. The rows below are the video's own published run (frame 0025), with one illustrative IS PF column added so the explorer can model the in-sample gate (the frame published only OOS/FULL). Defaults: --min-trades 300, --min-pf 1.0 (in-sample), --rank-by full_net. OOS metrics are validation, not the default rank key.

#AssetTFSide IS PF*FULL tradesFULL netOOS SharpeOOS PFOOS trades Verdict

*IS PF is illustrative — frame 0025 published only OOS/FULL columns; the value is added so the explorer can model the in-sample gate. A row failing it would be a cell-level NO_WINNER (no pass cleared the gate); FULL-trades failures are MIN_TRADES. Survivors past --per-asset are trimmed, not rejected.

The GOLD trap — ranking orders, it never certifies. Switch --rank-by to oos_sharpe and GOLD jumps to the top — but the video is explicit that gold ran up ~150–200%, so a long-only strategy's OOS curve is the asset, not the edge. full_net flatters the same trending asset (GOLD's net dwarfs the rest), which is why a high rank is never proof. The contract gates min-PF on the in-sample segment, makes OOS a validated flag (not a rank key), and leaves certification to the agent's asset-drift check (strategy return vs the asset's own return via rates).

Per-cell reject reasons (campaign continues): NO_WINNER (no pass cleared the in-sample gates), MIN_TRADES (winner's FULL trades too few), CELL_FAILED (a native launch failed; fail envelope embedded). Root ok:false is input-validation only (EMPTY_MATRIX, INVALID_SPLIT, INVALID_PARAM, INVALID_RANK_BY) plus the degenerate “no cell yielded any record” case — the frozen {ok,error} shape (mt5_cli/reports/envelope.py). Schema-version style mirrors stress.v1 and wake.v1.

Command contract

mt5 --json quant run \
  --expert my_strategy \
  --symbols EURUSD,XAUUSD,UKOIL,USDJPY \
  --tf H1,H2 \
  --from 2022-01-01 --to 2024-12-31 \
  --split 0.70 \                       # IS/OOS boundary: fraction or YYYY-MM-DD (MT5 ForwardDate)
  --param Risk=1.0,0.5,0.5,3.0 \       # NAME=value,start,step,stop  (repeatable)
  --param ATRWindow=20,10,5,30 \
  --mode genetic \
  --min-trades 300 --min-pf 1.0 --oos-min-pf 1.0 \   # min-pf is in-sample
  --rank-by full_net --per-asset 2 \   # full_net default; oos_sharpe/oos_pf opt-in (caveated)
  [--modelling ohlc-1m] [--no-html] [--dry-run] [--timeout 1800]

mt5 --json quant list                  # campaigns, newest first
mt5 --json quant show <campaign-id>

# new flag this feature adds, so the winner's set can be stressed:
mt5 --json tester ea stress --expert my_strategy --symbol XAUUSD --tf H1 \
  --from 2022-01-01 --to 2024-12-31 --set-file results/<child>/alpha.XAUUSD.H1.set
  • Exit code stays 0; callers parse the envelope's ok boolean (repo-wide rule).
  • run is CLI-only (launches a terminal, long-running). list/show are read-only and MCP-safe — matching how tester runs are not exposed over MCP.
  • --per-asset 2 keeps the top two per asset, exactly the rank-1/rank-2 layout of the video's summary table.

Operating as a quant — the agent loop

The commands are hands; this loop is the role. It ships as a static agent playbook (mt5_cli/skills/QUANT_WORKFLOW.md, the USER_WORKSPACE.md precedent) so any agent can introspect it. The agent brings the hypotheses and authors the EA — its own capabilities; the tool never holds the alpha.

Frame the hypothesis — what edge, which assets/timeframes, why it persists. Predeclare the universe before seeing results; keep rules simple.
Author & compile the EA — write the rule in ./ea/, expose search params as inputs, mt5 --json ea compile <name>.
Plan, then run the campaign — mt5 --json quant run … --dry-run to see the cost, then run with --min-trades 300 --min-pf 1.0 --rank-by full_net.
Read quant.v1 and judge — rank only orders candidates; start at the top, then apply the discipline below.
Stress the winner — mt5 --json tester ea stress … --set-file <winner.set>; require robustness.verdict robust/degraded before trusting it.
Iterate — refine hypothesis/params, re-run, log what lived or died (and whether the OOS window has been reused).
The judgment that makes it quant, not curve-fitting.
  • Asset-drift trap: a long-only winner on a trending asset (gold +150–200%) shows a gorgeous OOS curve that is the asset, not the edge. Make it actionable: fetch the asset's own move with mt5 --json rates fetch, compute buy-and-hold return, and subtract it — if the edge vanishes, it was never there.
  • Multiple testing: a big matrix × genetic search invites a lucky survivor; report how many cells and param combinations you tried, and don't treat rank-1 as validated.
  • Statistical weight: treat ~300 trades as a floor, not proof (clustering and one regime shrink the effective sample).
  • IS↔OOS consistency & overfitting: a validated entry whose OOS tracks its in-sample beats one that only shines OOS; fewer, meaningful params beat wide grids.
Honesty rules (also in the playbook). Final read in real-ticks (ohlc-1m understates execution cost); a single-asset, single-broker result is not validated edge — name the broker-clock, spread/slippage, and cost-sensitivity caveats; never report a result the tester did not produce.

Spec seed

Ownership boundaries

  • New package mt5_cli/quant/ owns the campaign; it imports mt5_cli.tester.ea, writes zero strategy logic, and never imports MetaTrader5 (filesystem-only, like the tester package).
  • matrix.py — pure: expand/validate symbols×timeframes, parse --split (fraction or date), parse --param ranges.
  • passes.py — pure: read + join back↔forward optimization rows by pass id.
  • selection.py — pure: pick winner from passes, apply gates, rank, record rejects (the tester/stress.py analog).
  • report.py — pure: dependency-free HTML + inline-SVG equity curve. No matplotlib, no pandas.
  • campaign.py — orchestration: per-cell hybrid, serial launches, artifacts, quant.v1 assembly.
  • store.py — campaign-id + manifest.json read/write (reuses tester/cache.py conventions).
  • mt5/cli.py stays a thin flag-parsing wrapper (CONTRIBUTING architecture rule).
  • mt5_cli/skills/QUANT_WORKFLOW.md — static agent playbook (the loop + judgment), shipped like USER_WORKSPACE.md.

Public interfaces

  • quant.campaign.run(*, expert, symbols, timeframes, from_date, to_date, split, params, mode, selection, …) → quant.v1
  • quant.list_campaigns() / quant.get_campaign(id)
  • mt5 quant run | list | show; new tester ea stress --set-file
  • New mt5_cli/quant/passes.py joins back↔forward (wraps results.parse_optimization_xml, back/forward-blind today).
  • Root errors: EMPTY_MATRIX, INVALID_SPLIT, INVALID_PARAM, INVALID_RANK_BY. Per-cell reject reasons: NO_WINNER, MIN_TRADES, CELL_FAILED.

Build sequence

  • 1 — matrix.py (expansion, split, param ranges) + tests
  • 2 — forward-aware parse_optimization_xml + fixtures
  • 3 — selection.py (winner pick, gates, ranking) + tests
  • 4 — campaign.py orchestration against a fake launcher
  • 5 — report.py (HTML/SVG) + store.py + tests
  • 6 — CLI group + error registry + quant agent playbook (ships with the CLI)
  • 7 — README / AGENTS / describe catalog / CHANGELOG; flip spec & plan status

Non-goals (YAGNI)

  • No Python EDA engine (return distribution, weekday×hour heatmap, autocorrelation) — that needs numpy/pandas the charter excludes.
  • No Python vectorized backtester and no Python→MQL5 translation — MT5 stays the only engine; the EA stays the only alpha.
  • No walk-forward beyond the single forward split; no multi-data-feed / news (CPI/FOMC/NFP) testing.
  • No campaign resume in v1 (each child run is cached, so resume can come later).
  • No trading strategy, signal generation, indicator math, or market opinion.
